## Q3 2026 (Jul–Sep) — realize the banked value + start the pilots

1. **Fable-window verification (before 08-07).** Adversarially verify the 122 FILE-FIRST
   evidence rows and fact-check the claims in both paper drafts with Fable 5
   (`claude-fable-5`) as the judge — the highest-judgment gate while the trial window lasts.
2. **Umbrella CORRECTIONS issue, no OCR gate** (adapts
   [HANDOFF_NEXT.md Task 1](https://github.com/drdhaval2785/SanskritSpellCheck/blob/master/HANDOFF_NEXT.md)):
   pilot the **SHS section** (37 candidates) → M.G. confirms format → scale to all 11 dicts →
   one evidence-rich issue body in `corrections_draft/CORRECTIONS_umbrella_issue.md`; **M.G. posts it**
   to [sanskrit-lexicon/CORRECTIONS](https://github.com/sanskrit-lexicon/CORRECTIONS/issues).
   `make_changefiles.py` drafts prepared per dict. Never bot-applied.
3. **Human loop:** M.G. scan-verifies (SHS → YAT → ACC first) and authorizes applying to
   `csl-orig` per the canonical correction workflow. Target: the first batch applied this quarter.
4. **Prior-art scan** → `docs/PRIOR_ART.md`: [sanskrit-spellchecker.netlify.app](https://sanskrit-spellchecker.netlify.app)
   (approach, data, license, maintenance), plus any other Sanskrit spellcheckers / Hunspell-sa /
   sanscript-ecosystem tools on the web. Feeds the web-app design AND both papers' related-work.
5. **Union-across-runs recall harvest (pilot, generous budget):** the LLM TYPO pass is stochastic —
   re-run `/dict-triage` N times on the 11 fileable dicts, union the FILE-FIRST sets, gate every
   new candidate through the Opus review phase. Never overwrite a committed package; union only.
6. **SHS entry-body deterministic pilot:** extend charset/phonotactic/ngram detection from headwords
   into entry bodies of SHS (poorly-digitised → highest expected yield). Measure precision on a
   human-verified sample before any scale-up.
7. **Chandas pilot (tiny scope — M.G. 02-07-2026):** one session, `skrutable` + `chanda` on one
   GRETIL text, diff verdicts, hand-check ~20 anomalies, fix the detector's output format; then
   park until Q1. Prior art:
   [docs/CHANDAS_ANUPRASA_PRIOR_ART.md](https://github.com/drdhaval2785/SanskritSpellCheck/blob/master/docs/CHANDAS_ANUPRASA_PRIOR_ART.md).
8. **Hub hygiene pass:** record SanskritSpellCheck as a `sanskrit-util` consumer in
   [SHARED_CODE.md](https://github.com/gasyoun/github-spine/blob/main/SHARED_CODE.md); register the
   do-not-file lists + reform maps as feeds in Uprava `PROJECT_INTERLINKS.md`; append the drift and
   triage-precision findings to `SanskritLexicography/FINDINGS.md` (Sanskrit-data) and Uprava
   `FINDINGS.md` (infra: the 429 throttle, tesseract gate); keep GTD pointers current.

## Q1 2027 (Jan–Mar) — productize

1. **PyPI package** (working name `sanskrit-spellcheck`): `slp1util`, the confusion model, the
   detector CLI (`run_all`) as an installable library with tests + docs; consumes
   [sanskrit-util](https://github.com/gasyoun/sanskrit-util) rather than vendoring transcoders.
2. **Web spellchecker app — new repo + GitHub Pages:** client-side (paste IAST/SLP1/Devanāgarī →
   suspects + ranked suggestions), grounded in the confusion model + union headwords + DCS bands;
   design informed by the Q3 prior-art scan; cite the netlify tool where due.
3. **Corpus expansion:** full DCS sqlite (VisualDCS release) for exact counts + morphology;
   GRETIL ingestion so "unattested" strengthens; recalibrate `dict_vs_corpus` and re-run `eval.py`
   (false positives must stay 0).
4. **Batch chandas validator — new detector family** (scaled up from the Q3 pilot): meter-validate
   GRETIL/DCS verse corpora with skrutable (has a "Scan GRETIL" batch mode) + `chanda`
   (per-syllable Levenshtein edit-ops) as an ensemble; pāda-level meter breaks become suspect-text
   candidates in the existing tier/review pipeline. Swap in / cross-validate the UoHyd student
   checker when the code is acquired (M.G. contact path; not public). Prior art + glue list:
   [docs/CHANDAS_ANUPRASA_PRIOR_ART.md](https://github.com/drdhaval2785/SanskritSpellCheck/blob/master/docs/CHANDAS_ANUPRASA_PRIOR_ART.md).
5. **Anuprāsa reimplementation** (clean-room from Barbadikar & Kulkarni 2024 — code unpublished,
   algorithm fully specified): SLP1-native library for (a) corpus sound-figure annotation,
   (b) SanskritKaraoke display enrichment, (c) the computational-alaṅkāra paper angle.
6. **Body check scale-up (per pilot results)** + **file batch 3.**

## Standing constraints (carry into every session)

- **`csl-orig` is read-only by default** — corrections applied only with explicit M.G.
  authorization, via the canonical workflow (XML validation before commit; no BOMs).
- **Maintainer noise sensitivity** — one umbrella issue, batched follow-ups, edit-in-place;
  never per-word issues, never bot-applied edits.
- **Cologne `servepdf` sustained-429s this IP** — scan fetches from a different network or
  server-side only; polite rates always.
- **The LLM TYPO pass is stochastic** — never blindly re-run/overwrite a committed triage
  package; recall grows by union-across-runs only.
- **Model attribution** — report tier AND version (e.g. Opus 4.8 `claude-opus-4-8`) for every
  step of every run, per-phase in multi-agent workflows.
- **Refuted paths — do not re-attempt:** corpus-based tier-C promotion (R-tier ceiling), vidyut
  attestation gate (R6), model-free body metrics in the ranker (R5). The body must be *read*.
